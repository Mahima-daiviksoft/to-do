# Chapter 39 — End-to-End Testing and Real Browsers (Playwright, Puppeteer, Detox) and Where Jest Fits

> 🧸 **Explain it like I'm 5**
>
> jsdom is a paper browser. Sometimes you need the **real thing**: a real Chrome that lays out
> pixels, plays videos and runs your whole app. End-to-end (E2E) tests drive a real browser (or
> phone) like a person would. Some E2E tools have their own runner; some can be driven from Jest.

Verified (October 2026): driving real Chromium from a Jest 30.5.2 test with `playwright-core`.

---

## 39.1 The landscape

| Tool | Runner | Targets | Relation to Jest |
| --- | --- | --- | --- |
| **Playwright Test** (`@playwright/test`) | its own runner (Jest-like `test`/`expect` API) | Chromium, Firefox, WebKit, Electron; component testing | **separate from Jest** — recommended way to use Playwright |
| **Playwright library** (`playwright`/`playwright-core`) | any (e.g. Jest) | same browsers | you can drive it from Jest (39.2) |
| **Puppeteer** | any; `jest-puppeteer` preset | Chrome/Firefox | Jest integration via `jest-puppeteer` (environment + globals `browser`, `page`) |
| **Cypress** | own runner (Mocha-based) | Chromium-family, Firefox, WebKit (experimental) | separate |
| **Detox** | uses **Jest as its test runner** | iOS/Android (React Native) | Jest config + Detox environment |
| **Maestro**, **Appium/WebdriverIO** | own runners | mobile | separate |

🎯 Interview point: "Is Playwright a Jest replacement?" — Different layers. Jest (with jsdom) for
unit/integration; Playwright for E2E and real-browser component tests. Playwright Test's API looks
like Jest, but it's a different runner with its own fixtures, retries, parallelism and tracing.

## 39.2 Driving a real browser from Jest (verified)

```js
/** @jest-environment node */
const { chromium } = require('playwright-core');

let browser;
let page;

beforeAll(async () => {
  browser = await chromium.launch();           // or { executablePath } for a preinstalled Chromium
  page = await browser.newPage();
}, 30_000);

afterAll(async () => {
  await browser?.close();                      // otherwise: "Jest did not exit…"
});

test('real browser: layout and real events', async () => {
  await page.setContent(`
    <button id="b" style="width:120px;height:40px">Hi</button><p id="out"></p>
    <script>document.getElementById('b').onclick = () => { document.getElementById('out').textContent = 'clicked'; };</script>
  `);
  const box = await page.locator('#b').boundingBox();
  expect(box.width).toBe(120);                  // real layout (jsdom always says 0)
  await page.click('#b');
  await expect(page.locator('#out').textContent()).resolves.toBe('clicked');
}, 30_000);
```

Notes:
- Use the **node** environment — the browser is a separate process, not jsdom.
- Increase timeouts (browser startup) and close the browser in `afterAll`.
- Run these in a **separate Jest project** (`displayName: 'e2e'`, `maxWorkers` limited) so unit
  tests stay fast: `jest --selectProjects unit` locally, both in CI.
- For most teams, `@playwright/test` is better for E2E (auto-waiting `expect`, traces, retries,
  sharding, HTML report). Driving it from Jest makes sense when you need to stay inside one runner
  (e.g. a Jest-only monorepo tooling constraint) or for small browser-backed checks.

## 39.3 jest-puppeteer

```js
// jest.config.js (e2e project)
module.exports = {
  preset: 'jest-puppeteer',              // provides globals: browser, page, context
  testMatch: ['**/e2e/**/*.test.js'],
};
```

```js
// jest-puppeteer.config.js
module.exports = {
  launch: { headless: 'new' },
  server: { command: 'npm run start', port: 3000, launchTimeout: 30_000 },  // starts your app
};
```

```js
test('home page', async () => {
  await page.goto('http://localhost:3000');
  await expect(page.title()).resolves.toMatch('My App');
});
```

(`expect-puppeteer` adds `await expect(page).toClick('button', { text: 'Save' })` style matchers.)

## 39.4 Detox (React Native E2E with Jest)

Detox builds and launches your iOS/Android app on a simulator/emulator; Jest is the runner:

```js
// e2e/jest.config.js (generated by `detox init`)
module.exports = {
  rootDir: '..',
  testMatch: ['<rootDir>/e2e/**/*.test.js'],
  testTimeout: 120000,
  maxWorkers: 1,
  globalSetup: 'detox/runners/jest/globalSetup',
  globalTeardown: 'detox/runners/jest/globalTeardown',
  reporters: ['detox/runners/jest/reporter'],
  testEnvironment: 'detox/runners/jest/testEnvironment',
  verbose: true,
};
```

```js
// e2e/todo.test.js — for this repository's TodoApp
describe('Todo app', () => {
  beforeAll(async () => { await device.launchApp(); });
  beforeEach(async () => { await device.reloadReactNative(); });

  it('adds a task', async () => {
    await element(by.text('Enter a task')).typeText('Buy milk');   // placeholder text
    await element(by.text('Add Task')).tap();
    await expect(element(by.text('Buy milk'))).toBeVisible();
  });
});
```

(Detox needs a built app binary and simulators — it can't run in a plain Linux container; this
example is not executed here. Prefer `testID` props + `by.id()` for stable selectors.)

## 39.5 What belongs in E2E vs Jest

| Concern | Jest (unit/integration) | E2E |
| --- | --- | --- |
| Business logic, edge cases | ✅ | ❌ (too slow) |
| Component behaviour, forms, state | ✅ (RTL/RNTL) | a few critical paths |
| Real layout, CSS, responsive behaviour | ❌ | ✅ |
| Canvas pixels, video, workers, real storage quotas | ❌ (fakes only) | ✅ |
| Routing across pages, auth redirects, cookies | partially | ✅ |
| Third-party scripts, payments in sandbox | ❌ | ✅ (or contract tests) |
| Async server components / streaming (Next.js) | top-level only | ✅ |
| Visual regression | ❌ | ✅ (screenshots) |
| Accessibility contrast | ❌ | ✅ |

💼 Keep E2E suites **small and focused on user journeys**; they're slower and flakier. Use stable
selectors (roles, test IDs), seed test data through APIs, isolate accounts per test, and record
traces/videos on failure.

## 39.6 Summary

- Jest + jsdom ≠ a browser. For real rendering, use Playwright/Puppeteer/Cypress (web) or Detox
  (React Native).
- You *can* drive Playwright/Puppeteer from Jest (node env, long timeouts, close the browser), but
  Playwright Test is usually the better E2E runner.
- Detox uses Jest as its runner for mobile E2E.
- Push logic down to fast Jest tests; keep E2E for journeys and real-browser concerns.
